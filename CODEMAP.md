## 2. Project Overview

A single Verilog module, `lcd_controller`, drives an HD44780 LCD in 8-bit, write-only mode.

- **Input:** the board clock (`clk`, default 50 MHz) and an active-high reset (`rst`).
- **Processing:** a clock divider makes a one-cycle `tick` every `EN_US` µs (default 50 µs). On each tick, an 11-state FSM moves one step. It waits about 20 ms for power-on, then sends Function Set (0x38), Display On (0x0C) and Clear (0x01). After that comes a separate ~2 ms wait (`CLEAR_WAIT`), then Entry Mode (0x06). It then sets the DDRAM address to line 1 (0x80), streams 11 ASCII bytes, sets line 2 (0xC0), and streams 12 bytes.
- **Output:** the LCD bus (`rs`, `rw`=0, `en`, `data[7:0]`) and a `ready` flag that goes high in `S_DONE`.
- **Message text:** hard-coded in a ROM initialised by an `initial` block: "SALSABEEL K" / "SPARTAN6 LCD".

The busy flag is never read (`rw` is tied low), so correct behaviour depends entirely on the delays being long enough. The repo also contains a self-checking Icarus testbench, a Makefile for simulation, and an ISE UCF constraints **template** whose pin LOCs are placeholders. The project has no software runtime, no external services and no storage.

Provenance (DOCUMENTED): the design was adapted from an unidentified open-source HD44780 driver. The original `.v` was lost; this file is a reconstruction plus a fix (the missing Clear Display delay).

## 4. Component Map

### Component: Tick Generator (`tick_generator`)
- **Purpose:** divides `clk` into a single-cycle `tick` strobe every `EN_US` µs.
- **Files:** `rtl/lcd_controller.v` (lines ~40–48)
- **Inputs:** `clk`, `rst`. **Outputs:** `tick`.
- **Depends on:** parameters `CLK_HZ`, `EN_US`. **Used by:** `lcd_fsm`.
- **Behaviour:** `TICKS = (CLK_HZ/1_000_000)*EN_US`. The counter `div` is sized with `$clog2(TICKS+1)`. `tick` is registered and is high for one clock when `div == TICKS-1`.
- **Evidence:** VERIFIED.

### Component: LCD FSM (`lcd_fsm`)
- **Purpose:** carries out the HD44780 init sequence and the character writes.
- **Files:** `rtl/lcd_controller.v` (FSM `always` block, `task pulse`)
- **Inputs:** `tick`, `rst`, `message_rom`. **Outputs:** `rs`, `en`, `data[7:0]`, `ready`; `rw` is constant 0.
- **Depends on:** `tick_generator`, `message_rom`. **Used by:** the top level / the board (via UCF), `sim_verification`.
- **Behaviour:** 11 states (`S_POWER_UP`…`S_DONE`, 4-bit encoding). Every byte takes 2 ticks: phase 0 drives the byte and sets EN=1, and phase 1 sets EN=0 and advances. The LCD latches on the falling edge of EN. `wait_ctr` (16-bit) is shared by `S_POWER_UP` and `S_CLEAR_WAIT`. `char_count` (4-bit) indexes the ROM.
- **Config:** `BOOT_TICKS = 20000/EN_US + 1`, `CLEAR_TICKS = 2000/EN_US + 1`.
- **Evidence:** VERIFIED.

### Component: Message ROM (`message_rom`)
- **Purpose:** holds the two display strings.
- **Files:** `rtl/lcd_controller.v` (`line1`, `line2`, `LEN1 = 11`, `LEN2 = 12`)
- **Outputs:** ASCII bytes to `lcd_fsm`.
- **Behaviour:** `reg` arrays filled by an `initial` block. To change the text, edit the arrays **and** `LEN1`/`LEN2`, keeping each at 16 or less (16 columns; `char_count` is 4 bits).
- **Evidence:** VERIFIED. The 16-character limit is INFERRED from the display width and the counter width.

### Component: Simulation Verification (`sim_verification`)
- **Purpose:** checks the byte stream and the Clear Display delay.
- **Files:** `tb/lcd_controller_tb.v`, `Makefile`
- **Inputs:** a DUT instantiated with `CLK_HZ = 1_000_000`, `EN_US = 2` (compressed timing) and a 10 ns sim clock.
- **Outputs:** console PASS/FAIL and `lcd_sim.vcd`.
- **Behaviour:** on `negedge en`, compares `{rs, data}` with `exp_data`/`exp_rs` (N = 28). After `ready` it checks `dut.CLEAR_TICKS * dut.EN_US >= 1520` µs.
- **Evidence:** VERIFIED. ⚠ Covers only 28 of the 29 bytes the DUT writes (see §14).

### Component: FPGA Integration (`fpga_integration`)
- **Purpose:** maps ports to pins and constrains the clock for Xilinx ISE.
- **Files:** `constraints/lcd_controller.ucf`
- **Behaviour:** sets the clock PERIOD to 20 ns (50 MHz). All I/O is LVCMOS33. LCD outputs use `DRIVE = 8` and `SLEW = SLOW`, and `rst` uses `PULLDOWN`. `ready` → LED is commented out.
- **Evidence:** VERIFIED. **All LOC values are placeholders** (P123–P143).

## 7. Main Workflows

### W1 — Power-on display sequence (hardware/RTL)
1. `rst` deasserts; FSM is in `S_POWER_UP`.
2. Wait `BOOT_TICKS` ticks (≈20 ms at the defaults).
3. `S_FUNCTION` 0x38 → `S_DISP_ON` 0x0C → `S_CLEAR` 0x01 (each takes 2 ticks via `pulse`).
4. `S_CLEAR_WAIT`: wait `CLEAR_TICKS` ticks (≈2 ms).
5. `S_ENTRY` 0x06 → `S_SET_LINE1` 0x80.
6. `S_WRITE1`: rs=1, 11 bytes from `line1`, then `char_count` resets.
7. `S_SET_LINE2` 0xC0 → `S_WRITE2`: 12 bytes from `line2`.
8. `S_DONE`: EN held low, `ready` = 1. The sequence never runs again unless reset.

### W2 — Simulation
1. `make sim` (or `iverilog -g2012 … && vvp lcd.out`).
2. Release reset at 100 ns; the checker logs each byte on `negedge en`.
3. `wait(ready)`, then +1000 ns.
4. Clear-delay check from the parameters; print `ALL CHECKS PASSED` or the failure count.
5. Optional: `make wave` opens `lcd_sim.vcd` in GTKWave.

### W3 — FPGA build (ISE)
1. Replace every LOC in the UCF using the board schematic.
2. Synthesise and implement `rtl/lcd_controller.v` with the UCF in Xilinx ISE (Vivado does not support Spartan-6).
3. Generate the bitstream and program the board. Exact ISE project settings: UNKNOWN / NOT DOCUMENTED.

## 8. Data Flow

```
clk ─► divider ─► tick ─► FSM state step
                           │
 message ROM ─(char_count)─┤
 CMD_* constants ──────────┤
                           ▼
          rs/data driven, EN↑ (phase 0) ─► EN↓ (phase 1) ─► LCD latches byte
                           ▼
                     S_DONE ─► ready=1
```
There is no input data path: the only inputs are clock and reset, and the output is fully determined by the parameters and the ROM.

## 9. Important Logic

| Logic | What it does | Why | Where | Assumptions |
|---|---|---|---|---|
| Tick-paced FSM | All timing is a multiple of one `EN_US` tick | One clock-independent time base; changing `CLK_HZ` keeps the µs timing | `TICKS`, `tick` | `CLK_HZ` is a multiple of 1 MHz (integer division) |
| `pulse(next)` task | Two-phase EN strobe for command bytes | Reuses one strobe pattern across all command states | `task pulse` | Byte stays stable through both phases |
| `CLEAR_WAIT` | ~2.05 ms wait after 0x01 | Clear Display needs 1.52 ms; other commands need ~37 µs | `S_CLEAR_WAIT`, `CLEAR_TICKS` | `EN_US` ≥ 37 µs so a single tick covers ordinary commands |
| Power-on wait | ~20 ms before the first command | HD44780 needs >15 ms after Vdd | `S_POWER_UP`, `BOOT_TICKS` | Reset released after the LCD is powered |
| Write loop | Self-loop with `char_count++`, exits at `LENx-1` | Streams ASCII | `S_WRITE1`, `S_WRITE2` | `LENx` ≤ 16 |
| Datasheet-check TB | Checks the delay from parameters, not sim time | TB uses compressed timing | TB final `initial` | Hierarchical refs `dut.CLEAR_TICKS` are supported by the simulator |

## 18. Stage 1 Learning Facts

1. The design drives an HD44780 16×2 LCD in 8-bit mode. — `rtl/lcd_controller.v` header
2. `rw` is tied to 0, so the busy flag is never read and all waits are fixed delays. — `assign rw = 1'b0`
3. `rs = 0` selects a command and `rs = 1` selects character data. — rtl ports
4. The HD44780 latches the bus on the falling edge of EN. — rtl header, TB `negedge en`
5. One tick = `EN_US` µs; `TICKS = (CLK_HZ/1_000_000)*EN_US` clocks. — rtl
6. The default clock is 50 MHz and the default `EN_US` is 50 µs. — rtl parameters, UCF `TS_clk`
7. The FSM has 11 states, from `S_POWER_UP` to `S_DONE`, in a 4-bit encoding. — rtl
8. The init order is 0x38 → 0x0C → 0x01 → (wait) → 0x06 → 0x80. — rtl, TB
9. 0x38 = 8-bit, 2-line, 5×8 font. 0x0C = display on, cursor off. 0x06 = increment, no shift. — rtl `CMD_*`
10. 0x80 and 0xC0 are the DDRAM start addresses of lines 1 and 2. — rtl
11. Power-on wait = `BOOT_TICKS = 20000/EN_US + 1` (401 ticks ≈ 20 ms; the datasheet needs >15 ms). — rtl, README
12. Clear Display takes 1.52 ms. `CLEAR_TICKS = 2000/EN_US + 1` (41 ticks ≈ 2.05 ms). — rtl, README
13. Without `CLEAR_WAIT`, the command after Clear is ignored and the first characters of line 1 go missing. — rtl comment, README
14. Each byte uses 2 ticks: phase 0 drives the byte with EN high, phase 1 drives EN low. — `pulse`, `phase`
15. `wait_ctr` is shared by `S_POWER_UP` and `S_CLEAR_WAIT`. — rtl
16. Line 1 is "SALSABEEL K" (11 chars); line 2 is "SPARTAN6 LCD" (12 chars). — rtl ROM
17. `ready` is high only in `S_DONE`. — `assign ready`
18. The TB runs with `CLK_HZ = 1 MHz`, `EN_US = 2` to compress time. — TB
19. The TB checks Clear timing from `dut.CLEAR_TICKS * dut.EN_US`, not from simulation time. — TB
20. A Spartan-6 bitstream requires Xilinx ISE; Vivado does not support Spartan-6. — README
21. The UCF LOCs are placeholders that must be replaced. — UCF header
22. LCD outputs use LVCMOS33, DRIVE 8, SLEW SLOW to tolerate ribbon cables. — UCF
23. Reset is synchronous and active high, and returns the FSM to `S_POWER_UP`. — rtl
24. The current RTL is a reconstruction of a lost original and has not been re-run on hardware. — README Provenance

## 19. Stage 2 Candidates

### `lcd_fsm`
- **Why:** sequencing, two-phase strobes and datasheet timing all meet here.
- **Files / symbols:** `rtl/lcd_controller.v`: `state`, `phase`, `pulse`, `wait_ctr`, `char_count`, `S_CLEAR_WAIT`.
- **Prediction questions:** how many ticks from reset to `ready`; what `data`/`en` are on a given tick; timing at a different `EN_US`.
- **Failure questions:** removing `S_CLEAR_WAIT`; `EN_US < 37`; `LEN1 > 16`; reset mid-write.
- **Modification questions:** add a third command (e.g. cursor on); make the message loop/refresh; add 4-bit mode; present the byte a tick before EN↑ (F4).

### `tick_generator`
- **Why:** parameter arithmetic and integer-division pitfalls.
- **Symbols:** `TICKS`, `div`, `$clog2`, `tick`.
- **Prediction:** `TICKS` and the `div` width for given params. **Failure:** `CLK_HZ = 33.333 MHz` (F6). **Modification:** a ns-resolution divider.

### `sim_verification`
- **Why:** self-checking TB design and compressed timing.
- **Symbols:** `N`, `exp_data`, `exp_rs`, `negedge en` checker, `clear_us`.
- **Prediction:** what the TB prints if `CLEAR_TICKS` is halved. **Failure:** the missing 29th byte (F3). **Modification:** add a power-on-delay check and EN pulse-width assertions.
